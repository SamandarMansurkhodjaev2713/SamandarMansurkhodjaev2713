## Как я обеспечиваю качество

- начинаю с требований, рисков и критериев приёмки, а не с хаотичной проверки готового интерфейса;
- выбираю слой проверки по цене дефекта: domain/unit, API и интеграции, данные/SQL, UI и критичные E2E-пути;
- автоматизирую стабильные повторяемые проверки, а исследовательское тестирование оставляю человеку;
- использую Playwright, pytest, Vitest/Jest, xUnit, Postman/Newman, SQL, DevTools, Docker и GitHub Actions по назначению;
- фиксирую не только «готово», но и ограничения, точки отказа, диагностику, критерии релиза и остаточный риск.
